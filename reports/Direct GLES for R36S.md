# Preserve Zandronum, replace its graphics path

**Full direct GLES backend should retain Zandronum 3.2.1 scene preparation and simulation, replacing desktop OpenGL submission with buffered vertices, explicit transforms and mandatory GLES shaders.** Maximum practical GZDoom reuse lies in its permissively licensed buffer, texture, sampler and shader compiler components; modern renderer transplant would import unrelated engine interfaces and licensing obligations. Existing shader sources provide compatible starting lineage for preserving Zandronum effects. Native 640×480, stock firmware Mali EGL/GLES, offline PortMaster packaging and existing controls/audio/lifecycle remain release requirements. Research identifies concrete conversion surface and acceptance gates; **no direct GLES binary or device performance result exists at research cutoff**. Smooth 60 FPS remains measured objective, not consequence assumed from removing GL4ES. ([Existing renderer](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/src/gl/renderer/gl_renderer.cpp#L101), [donor buffers](https://github.com/ZDoom/gzdoom/blob/c26ce2e6ca2a0c770f140cb25dde0d30073ca8f7/src/common/rendering/gles/gles_buffers.cpp#L1-L34), [release scope](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/docs/specs/zandronum-3.2.1-arm64-r36s.md))

## Native GLES belongs below existing scene preparation

Research baseline is isolated branch `r36s-gles`, commit **`178fbce175adc2cc3fca645d66d4c9bebaf5d8b1`**. Existing `FGLRenderer` and `FGLInterface` already prepare geometry and organize opaque, masked, lit, decal, gap-fill and translucent passes. Preserve those calculations and ordering. New compile-time GLES build should replace low-level draw, transform and shader/state implementation while desktop build retains original loader and API. Software renderer and headless server should remain supported. This seam limits changes to rendering rather than actor state, simulation arithmetic, serialization or protocol definitions. Preservation remains design intent until save/demo/server tests verify it. ([Renderer initialization](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/src/gl/renderer/gl_renderer.cpp#L101), [scene passes](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/src/gl/scene/gl_scene.cpp#L378), [engine interface](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/src/gl/scene/gl_scene.cpp#L1134))

**Relinking cannot achieve this conversion.** Current headers include GLEW and declare desktop function-pointer globals with names colliding with GLES core symbols. Capability initialization assumes desktop version strings and ARB entry points. Existing shader-model 4 path still deliberately uses program zero for ordinary 2D and falls back to fixed texture/fog/texgen state. GLES requires separate API inclusion and capability initialization; every drawing path requires valid program, including requests currently named `forcenoshader`. Cached alpha-state branch also contains mismatched `glBlendFunc` call, so merely switching `gl_direct_state_change` off would preserve incorrect behavior. ([API boundary](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/src/gl/system/gl_system.h#L96), [loader](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/src/gl/system/gl_interface.cpp#L157), [state/shader selection](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/src/gl/renderer/gl_renderstate.cpp#L153), [cached state](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/src/gl/renderer/gl_renderstate.cpp#L298))

Engine audit identified **48 lexical `glBegin` sites across 14 files**, including one Windows-only test; Linux scope contains 47 source sites, plus flat VBO draws and voxel indexed quads. These counts describe conversion sites, not per-frame draw calls. Proposed drawing object should explicitly own position, UV, vertex color, normals and fog/glow/light inputs, primitive assembly, static/streamed buffers, transforms and legal index formats. Quads become triangles; strips preserve alternating winding; fans preserve split edges and interpolation. Matrix conversion must preserve multiplication order, texture transforms, model transform currently stored in texture matrix 7, and normal transform for sphere maps. **Batching requires captured state or flushes before material, texture, matrix, shader, depth, stencil, framebuffer and readback changes.** Translucent and portal ordering cannot change to increase batch size. ([Wall vertices](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/src/gl/scene/gl_walls_draw.cpp#L223), [flat VBO](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/src/gl/scene/gl_flats.cpp#L286), [voxel quads](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/src/gl/models/gl_voxels.cpp#L513), [shader transforms](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/wadsrc/static/shaders/glsl/main.vp#L16-L75))

License selection affects distributable implementation. Zandronum README limits its GPL-compatible new-code license to Zandronum-specific work; `doomdef.h` and `p_mobj.cpp` still retain Doom Source Code License notices. Research did not establish blanket GPLv3 compatibility across combined older engine. Safe implementation route uses explicit BSD/zlib donor pieces with original notices, full donor SHA/path and adapted-function manifest, while retaining local shader lineage. LGPL reuse remains possible only after combined-work/source/rebuild obligations are handled; source availability alone is insufficient compliance evidence. **This restricts which code can be copied; it does not block direct GLES work.** ([Zandronum license scope](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/README.md#L46-L53), [legacy header](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/src/doomdef.h#L1-L15), [distribution requirements](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/LICENSE.txt#L1-L28))

Donor baseline genuinely supports ES2/GLSL100 with CPU staging and `glBufferSubData`, rather than requiring persistent mapping. It queries NPOT, packed depth-stencil, depth-clamp and anisotropy capabilities. ES3 should be selected only after actual device context confirms it; ES3 removes some format/index constraints but does not restore immediate mode or fixed matrix/alpha/texenv semantics. Donor also disables user shaders, leaves fragment clip discard commented out, and records packed model-normal TODO. Its shader variants compile at first use, introducing potential hitch source unless required variants are warmed before gameplay. These observations make donor useful engineering reference but insufficient proof of full Zandronum feature fidelity or smoothness. ([Capabilities](https://github.com/ZDoom/gzdoom/blob/c26ce2e6ca2a0c770f140cb25dde0d30073ca8f7/src/common/rendering/gles/gles_system.cpp#L8-L236), [buffer path](https://github.com/ZDoom/gzdoom/blob/c26ce2e6ca2a0c770f140cb25dde0d30073ca8f7/src/common/rendering/gles/gles_buffers.cpp#L96-L164), [normal TODO](https://github.com/ZDoom/gzdoom/blob/c26ce2e6ca2a0c770f140cb25dde0d30073ca8f7/src/common/rendering/gles/gles_buffers.cpp#L272-L278), [clip code](https://github.com/ZDoom/gzdoom/blob/c26ce2e6ca2a0c770f140cb25dde0d30073ca8f7/wadsrc/static/shaders_gles/glsl/main.fp#L470-L495), [variant compilation](https://github.com/ZDoom/gzdoom/blob/c26ce2e6ca2a0c770f140cb25dde0d30073ca8f7/src/common/rendering/gles/gles_shader.cpp#L682-L735))

## Complete conversion includes portals, wipes and device presentation

Implementation should freeze private geometry/transform/state contract before dividing edits. Platform build selects GLES headers/library and excludes desktop loader. Drawing object owns vertex/matrix assembly and streamed/static buffers. `FRenderState` owns mandatory program, blend/depth/stencil and uniform application. Texture implementation owns supported upload formats, mipmaps, filtering and FBO validation. This division follows existing local seams and avoids simultaneous ownership of mixed framebuffer/wipe files. First useful development milestone is complete compilable backend; **release work continues through every row below**, not stopping after first visible map. ## Release evidence must prove fidelity and frame cadence

Current baseline must be represented accurately. Earlier ARM64 missing geometry and duplicate skies were fixed through signed angle conversion/cache invalidation and sky-key representation copy; stale session memory describing unresolved geometry is superseded by repository evidence. GL4ES baseline still shows demanding-scene dips: documented MAP07 averaged **43.162 FPS**, minimum full five-second window **24.2 FPS**; fixed floor diagnostic averaged **27.327 FPS** with **32.264 ms CPU/frame** and **0.377 ms swap/frame**. Those measurements identify CPU-side pressure, not exclusive GL4ES root cause. Same content, camera, audio, lights, clocks, resolution and workload must be used for new comparison. ([Renderer fixes](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/docs/r36s-rendering.md), [baseline timing](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/docs/r36s-performance.md))

Proposed release evidence matrix expands existing package acceptance to changed backend. Each visual fixture needs manifest entry recording content hash, map/save/camera, commands/settings, expected reference and actual result. Original-game maps cannot exercise portals, custom shaders, models or camera textures, so targeted licensed/generated Zandronum-compatible fixtures are required before claiming complete renderer. Every capture needs build/runtime/source identity and raw result, and owner listening/control observations must remain distinct from automated screenshot or loopback evidence. ([Existing scope](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/docs/specs/zandronum-3.2.1-arm64-r36s.md), [physical acceptance](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/docs/r36s-single-player.md), [lifecycle procedure](https://github.com/ktodorow/zandronum_arm64/blob/178fbce175adc2cc3fca645d66d4c9bebaf5d8b1/docs/portmaster-testing.md))

## Conclusion

Recommended branch architecture gives each future failure identifiable owner: scene output, native vertex/state/shader contract, platform presentation or package integration. That makes complete implementation reviewable and allows correctness fixes to remain independent of performance tuning. Donor provenance and fixture coverage belong beside implementation, so “full renderer” becomes falsifiable release claim rather than label attached to first successful launch.

Research cutoff leaves actual ES capabilities, advanced fixture execution, direct GLES frame times and stock-server compatibility unproven. Branch readiness therefore depends on filling those evidence gaps with implemented backend and preserved device behavior. Report supplies implementation direction and completion gates; it records no release acceptance or 60 FPS result.
