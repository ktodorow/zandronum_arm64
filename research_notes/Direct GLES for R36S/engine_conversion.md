# Zandronum engine conversion for direct GLES on R36S

## What seam gives complete GLES renderer while preserving Zandronum and desktop GL?

### Takeaway
Use existing FGLRenderer scene preparation, BSP/clipping, draw lists, materials, model loaders, gameplay, and network engine. Add compile-time native GLES backend below FRenderState and geometry submission, with GLES shaders and explicit vertex/matrix inputs; keep desktop GL backend in separate build. Whole modern GZDoom renderer transplant would drag unrelated engine interfaces into old Zandronum. No runtime GL4ES dependency or exported desktop-GL compatibility layer should exist in GLES binary.

### Inferences
- Full native engine backend is substantially smaller than porting modern GZDoom engine wholesale, but cannot be library relink. Existing draw-list architecture should stay; use donor GZDoom GLES matrix/vertex/shader techniques after donor researcher verifies versions/licenses.
- Private engine-specific builder is acceptable if restricted to actual supported engine attributes/topologies and submits native GLES VBOs/shaders. Avoid general glBegin/glMatrix/glTexEnv API emulation with symbol interposition; that recreates GL4ES inside executable and conceals ownership.
- Final geometry submission should support batching compatible triangles across surfaces where safe. If first implementation submits one draw per former glEnd, it is direct GLES but performance is unqualified until draw counts and CPU times measured; no speedup promise follows from removing GL4ES alone.
- Preserve desktop backend using compile-time `USE_GLES`/equivalent option and native GLES library linkage, while desktop retains GLEW/GLU/old loader. Do not replace shared gl_system.h with GLES headers globally.

### Gaps
- Exact native GLES version/extensions, shader limits, depth/stencil formats, indexed32 support, and SDL context creation mechanism need actual R36S probe; device researcher owns these.
- Parent correction about current defaults/fixed geometry must be linked to latest release notes in consolidated report; this audit did not independently repeat hardware result.
