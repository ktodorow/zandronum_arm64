These are sampled PC proportions, not directly milliseconds/frame or guaranteed FPS gain. ## Recommendation and risk ranking

1. Keep accepted DBOPL1, native synth rate, full panning and voice count. Confirm actual run settings before further measurements. No new settings-only, exact-output optimization was found: accepted package already uses cheaper DBOPL. Main-thread callback cost is real work, not unnecessary polling.
2. Strongest fidelity-preserving implementation candidate: move steady-state stream refill/synthesis to owned music worker, preserving identical callback sizes, event segmentation, sample rate, core, chip count and queue contents. Pinned GZDoom supplies concrete permissive worker/lifetime design. This moves work off critical game thread; it does not reduce total synthesis or guarantee 60 FPS. Existing multicore contention, GPU cost and worker deadline remain device acceptance gates.
3. Worker is substantive lifetime/concurrency change, not safe isolated replacement of `IsEnded()`. Local MIDI callback, shutdown and decoder control need synchronization too. Prefer one clearly owned worker with explicit quiesce-before-control/destroy. If broad stream consumers cannot all be qualified, make asynchronous eligibility explicit and keep unqualified consumers synchronous; do not silently expose every legacy decoder/synth to new threading.
4. Same-core micro-optimization only after exact PC attribution inside DBOPL/OffsetSamples and offline PCM comparison. No measured redundant hot operation established here. DBOPL already skips inactive operators/channels. Changing floating-point contraction/fast-math, denormal handling, core, chip count, pan or sample rate is not an exact-output fix.

Music disabled is useful only as isolated diagnostic, never release policy. Changing callback size may distribute CPU work more evenly, but local DC correction makes it non-bit-exact without further proof; do not label it fidelity-preserving by assumption.

## Why smaller buffers are not proven exact

`src/oplsynth/opl_mus_player.cpp:226–295` splits each callback at MIDI ticks, updates chips, then calls OffsetSamples once per segment. `OffsetSamples:298–370` scans each segment min/max and largest position, chooses DC offset, ramps over up to512 samples (or shorter adaptive ramp), and stores LastOffset. Callback boundary is an additional segment boundary. A buffer-size change can change extrema, target offset and ramp, hence PCM, even with same note events and49716Hz. Preserve callback lengths/order for strict same-output worker implementation; no merge/split optimization by assumption.

## Local concurrency/lifecycle traps before implementation

1. **Plain bool Playing and registry lifetime.** Local stream constructor pushes raw pointer, destructor releases AL source/buffers before deleting registry entry (`oalsound.cpp:266–291`). Worker requires synchronized registry and remove/wait **before** first release, then decoder/Reader destruction. Renderer must stop/wake/join worker before deleting streams, AL sources, context or device (`932–973`). Avoid joining while holding mutex worker needs. Empty-registry wait and startup failure must also terminate.
2. **Stop semantics.** Local Stop checks Playing then stops/clears queue; worker Process may be inside callback. Stop must first quiesce callback before touching/deleting callback owner, then ensure no requeue/restart after Stop. All Play/Stop/replay operations need consistent state publication. Main thread must never wait for long worker refill during ordinary per-frame status polls.
3. **OPL CritSec mismatch.** Generic SoftSynth ServiceStream holds CritSec (`music_softsynth_mididevice.cpp:397–439`), StreamOutSync holds same CritSec (`242–245`), but OPL override simply invokes OPLmusicBlock::ServiceStream (`music_opl_mididevice.cpp:274–277`), which holds **ChipAccess only** (`opl_mus_player.cpp:236–295`). Adding only CritSec to main calls does not protect OPL Events/NextTickIn. Two base classes also each own timing state; preserve existing virtual dispatch/clock behavior.
4. **Callback enters MIDIStreamer, not just emulator.** OPL PlayTick delegates to SoftSynth PlayTick (`music_opl_mididevice.cpp:158–161`); when event buffer exhausted it calls Callback MOM_DONE (`music_softsynth_mididevice.cpp:357–367`). On SDL, `MIDIStreamer::Callback` calls ServiceEvent directly (`music_midistream.cpp:662–682`), refilling MUS/MIDI data and changing EndQueued/BufferNum/Events/tempo/loop state (`822–873`). These currently plain fields must have owned-thread discipline or coherent synchronization, not just atomic stream flag.
5. **Stop race/deadlock.** MIDIStreamer::Stop currently writes EndQueued=4 **before** MIDI->Stop (`488–514`), while worker callback reads/writes EndQueued and may use MIDI and embedded buffers. IsPlaying also reads EndQueued (`521–532`). A worker-safe ordering must quiesce callback first, then mutate/free state; public status needs atomic/snapshot or matching lock. Do not add song mutex around Stop then acquire StreamLock if worker holds StreamLock and invokes callback taking song mutex: ABBA deadlock. Choose one explicit lock order/ownership and test it.
6. **Destroy/reset/stats.** OPLMIDIDevice::Close deletes stream before OPLdeinit (`117–121`), good ordering only if delete quiesces. Raw OPLMUSSong destructor Stop then deletes Music (`music_mus_opl.cpp:42–49`), likewise needs quiescence. OPLMIDIDevice derives SoftSynth then OPLmusicBlock; implicit base destruction destroys OPLmusicBlock/io before SoftSynth destructor Close, so defensive explicit early Close is needed if any deletion path can leave stream active. GetStats reads mutable channels with no ChipAccess (`music_opl_mididevice.cpp:285–315`); synchronize/snapshot it. Runtime chip-reset CVar and raw Restart must not overlap refill.
7. **Decoded streams differ from modern donor.** Local callback reads Decoder/Looping; SetPosition directly seeks and calls IsEnded to refill (`oalsound.cpp:212–227,357–370`); GetPosition/GetStats read decoder offset. Broad worker adoption must serialize seek+stop+flush+refill and snapshot position; changing IsEnded to atomic query alone breaks seek. Preserve pause/resume, partial final-buffer/loop behavior, format and volume.
8. **Other callbacks.** Local CreateStream also serves module/GME/FluidSynth/other softsynth consumers; any broad worker must audit their control/lifetime and callbacks. OPL-only eligibility can bound initial scope, but unsupported content must remain correct using synchronous path. No assumption modern donor's external synth/decoder threading proof applies to legacy implementations.
9. **AL threading distinct from GL threading.** [OpenAL1.1spec](https://www.openal.org/documentation/openal-1.1-specification.pdf), section6.2, permits multiple threads sharing context. Existing process-current AL context can be shared; do not copy OpenGL exclusive-context rules or call alcMakeContextCurrent(NULL) on worker shutdown while main still uses it. [OpenAL maintainer explanation](https://openal.org/pipermail/openal/2023-April/000878.html) confirms process-global current context; [context lifetime clarification](https://openal.org/pipermail/openal/2023-May/000889.html) requires no concurrent calls at destruction. Library/driver serialization can still cause stalls. Confirm actual library's error-state behavior: [maintainer notes](https://openal.org/pipermail/openal/2014-May/000120.html) explain historic shared per-context errors, so concurrent alGetError consumers can misattribute errors on implementations without thread-local error state. Do not assume configuration-doc version proves installed library version.
